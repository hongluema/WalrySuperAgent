# Web 教学结构化输出与澄清恢复

适用：`web-teacher.v2` 教学控制器。未修改 cheerful-mini，也不迁移或重置已有学习记录。

## 输出适配

- 分类器首次生成和唯一一次修复都携带字段合同；修复还携带原始任务、上下文和逐字段校验错误。
- `requestedTopic: null`、空字符串，以及 `explicitAction: null / NONE / none` 规范为未指定动作。缺失分类理由使用明确的“模型未提供分类依据”，不伪造理由。缺失 target、primaryIntent、sessionCommand 等路由判断仍须修复并校验。
- Web 评估缺少 obstacle 时仅表示未取得障碍证据，不判定误区。可选 score 的 null 规范为省略。
- 候选题缺 expectedSignals 时，只使用当前节点已有、同一 purpose 的 rubric 锚点；没有锚点的候选不用于考核选题。允许空候选列表交由控制器恢复。
- 不补造学生原话、作答证据或掌握分数。两次模型输出都不可用时仍报告降级，不无限重试。

## 恢复路径

1. 评估失败时保留已有学习证据，回到当前节点的内容任务，不把服务错误变成学生要回答的澄清题。
2. 对“没什么需要澄清的，继续吧”“示范一个步骤”等明确操作请求，不记录能力证据或知识误区。
3. 澄清完成后按当前缺口选择全新的内容题。没有合格模型候选时，从绑定已有 rubric 的有限内容任务中选取；对全部候选和恢复题查重，不生成三选一帮助菜单。
4. 显式示范与评估分支都将正文和题卡绑定到同一个内容任务；示范标记 worked-example，提示仍标记 hint。
5. 恢复任务耗尽时清空待答题并说明暂时没有新题，保留进度；后续求助也不能重新挂已经用过的开场题。模型随后提供新的合格候选时可以继续。
6. 在证据已齐的疑问检查阶段，保留模型对“继续吧”的合法 no_doubts 判断，由原有确定性门槛决定是否过关。

## 不改变的门槛

- 澄清、求助和示范请求不算作答。
- 带 hint / worked-example 的正确回答最多记录 weak，后续仍需独立验证。
- 不能仅靠继续指令、模型评分或技术恢复标记掌握；原有 rubric、误区修复和疑问检查门槛继续生效。

## 验证

自动回归位于 `src/tutor/web-teaching.test.ts`。使用脚本化模型输出和真实控制器/文件存储，覆盖合同修复、null/NONE、缺失注解、双次无效 JSON、连续三轮澄清恢复、显式示范、恢复耗尽、无疑问过关和提示证据边界。未调用线上模型，不启动浏览器或服务。

手动验证：让后端进程加载新代码后，在原有卡住课程依次发送“没什么需要澄清的，继续吧”“示范一个步骤吧”“示范一个步骤”，检查题卡回到内容、正文帮助与题卡一致、进度没有因这些请求被虚增。再独立作答验证原有掌握门槛；无需新建课程或清空历史。
