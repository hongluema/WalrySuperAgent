# 提示应怎样帮助学生

## 问题来源与设计原则

截图中的「先给一个具体例子或步骤，不必概括整节课」来自恢复题固定文案。它说明回答形式，却没有提供新的操作或线索；而题目还要求学生自己构造例子，负担没有降低。这是恢复题设计的问题，不能只靠更热情的措辞解决。

这里把提示的作用定义为：**减少当前任务的一项困难，同时保留要由学生完成的关键判断**。这是本项目的设计准则，不是对所有学习场景的效果承诺。

一对问题和提示应满足：

1. 题目提供对象、情境和必要条件，不让学生猜缺失事实。
2. 提示解决一个障碍：注意哪里、先做哪一步、怎样表示或固定哪项条件。
3. 学生看后能立刻动手，仍需自己完成结论、关系或选择。
4. 不直接展示 rubric 合格信号，也不把答案改成反问。

## 通用与领域处理

通用处理是缩小范围、固定条件、拆开已知与推断、搭一个未完成的表示。专业处理按当前题实际要求的知识操作选择，不把「商业」「数学」等大类机械等同于某一种思考方式。

| 任务 | 有用的第一步 | 仍留给学生的判断 |
| --- | --- | --- |
| 因果解释 | 固定其他条件，画「条件变化 → [中间一步] → 结果」 | 第一跳影响哪个对象，怎样传到结果 |
| 数学推导 | 圈出相邻两行发生变化的符号，检查规则前提 | 该规则为何可用 |
| 代码/操作 | 列输入、操作、输出，跟踪一个输入 | 哪个步骤改变状态，为何影响下一步 |
| 概念辨析 | 构造只改变一个特征的一对情况 | 改变的是否是必要条件 |
| 语言表达 | 固定意思，标出听者和语境，只替换一个词 | 语气或含义是否合适 |
| 材料论证 | 分开列原文信息和主张 | 哪一段支持主张，是否多加假设 |
| 决策取舍 | 固定目标，只改变一项限制 | 原来的选择依据是否仍成立 |

## 本次实现

- 新规则限定 `web-teacher.v2`；课程构建显式传递策略，mini/legacy 不启用新增开场要求。
- 恢复题与提示成对保存；每个变体有自己的操作支架，撤掉所有题共用的固定提示。
- explained 恢复题按节点 knowledgeTypes 选择推导、因果、操作、语言、论证或决策任务；类型不足时使用材料与判断对应，不假装知道具体机制。
- 模型生成候选题和开场题时，明确要求具体情境、一步支架和不泄露答案，并让模型自检。
- Web 注解允许无提示。已知空话、整句重复题干会被移除；前端已有空提示不展示逻辑，无需增加按钮或拼造替代文案。
- 不改变 hintSeen、受助证据、掌握门槛与苏格拉底式提问策略。

确定性过滤只覆盖已知空话和整句复读，并不是通用语义质量检测器。恢复题只能提供方法支架，不能在缺少可靠模型输出时编造学科事实；它仍不等同于老师生成的具体领域案例。已有历史消息不批量改写，更新后新生成的题生效；旧题经显式帮助重新发送时会过滤已知空话。

按用户要求，本次不运行前后端测试、构建或浏览器验收；仅做代码阅读与静态审查。
