# 私教内容优先原则

对比 Sitor（参考实现）和 WalrySuperAgent 在同一个学习任务上的表现，沉淀出四条改进原则。

## 问题诊断

### 问题 1：诊断维度强制凑满

**现象**：硬编码要求四维诊断（既往经验、概念理解、边界辨析、迁移能力），导致某些主题产生无信号的题目。例如学习一本书时，"迁移能力"维度的诊断题往往只能问出自我评价，没有实际诊断价值。

**原则**：让模型根据主题自行选择 2-4 个最有区分度的维度。最低要求从 3 题降到 2 题。

### 问题 2：路线图混入教学方法论节点

**现象**：概念路线中出现"明确学习目标""批判性思考""形成应用清单"等节点，挤占了实际内容节点的位置。这些是教学技法，不是学习对象。

**原则**：路线节点必须是学习对象本身的知识/内容节点。判断标准——去掉这个节点后，学习者对该领域的理解是否有实质缺失？教学技法应融入内容节点的教学过程，不作为独立节点。对于有明确源材料的学习（书/论文/代码库），路线应忠于源材料自身的结构。

### 问题 3：诊断结果不影响路线起点

**现象**：即使学习者在诊断中明确答对了某个概念题，教学仍然从第一个节点开始，无法跳过已知概念。

**原则**：诊断编译器输出 `skipSuggestions`，标注学习者可能已掌握的节点及置信度。高置信度的跳过建议直接将节点标记为 `known`，教学从第一个非 known 节点开始。

### 问题 4：首轮教学陷入元讨论

**现象**：完成诊断后，首轮教学回复是"我们来明确一下学习目标""让我先帮你梳理学习计划"之类的元讨论，而非直接进入第一个内容节点的教学。

**原则**：首轮教学的 `firstTeachingDecision` 直接锚定到起始内容节点，`responsePlan` 聚焦于该节点的核心概念，不做元讨论。

## 跨场景通用性

这四条原则不依赖特定学习主题，适用于所有通用私教场景：

- **书籍学习**：诊断 2-3 题即可判断读者背景；路线忠于书的章节结构；答对的概念章节可跳过
- **技能学习**（编程、写作等）：诊断侧重已有实操经验和概念理解；路线是技能的核心组件，不是"设定目标→反思→总结"的通用流程
- **概念学习**（经济学原理、物理定律等）：诊断侧重先验概念和常见误解；路线是概念依赖链
- **项目式学习**：诊断侧重已有经验和工具熟悉度；路线是项目分解后的知识模块

## 实现改动摘要

| 文件 | 改动 |
|------|------|
| `model-client.ts` | 诊断维度 min 3→2；prompt 柔性维度 + 内容锚定；诊断输出 skipSuggestions |
| `types.ts` | TutorDiagnosis 新增 skipSuggestions 字段 |
| `orchestrator.ts` | 诊断后应用 skip 逻辑；firstTeachingDecision 接受起始索引 |
| `orchestrator.test.ts` | 新增 skipSuggestions 跳过逻辑测试 |
