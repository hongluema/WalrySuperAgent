# 读书模式

Web 新会话在输入框的模式菜单选择“读书”（`sessionMode: read`）。本会话模式锁定；教学、讲解保持原入口。支持书名、章节文本、读书笔记及现有材料入口；只有书名时参考搜索并说明资料边界，不能把检索摘要当全书原文。

## 阅读流程

开书与目的 → 全书主线 / 章节导读 → 精读论证、概念、案例、边界 → 整理笔记与疑问 → 独立解释、举例、应用 → 间隔复习 → 回到原始目的做全书总结。尊重直接讲解、跳章和暂不练习的选择；读过与已验证理解分开记录。

右侧阅读面板集中展示“进度、笔记、未解问题”，窄屏由右上角入口打开弹窗。查看这些资料只读取已保存的记录，不生成聊天消息、不消耗模型调用，也不改变阅读阶段。笔记随每轮阅读自动整理。面板底部的“继续精读、复习、应用练习”明确回到主会话发起学习。自然语言查询和同会话内跨书比较仍保留。

## 实现

- `book-study.ts`：阅读合同、笔记增量合并、掌握证据门槛、复习调度和公开进度摘要。
- `AiTutorModelClient`：先整理结构化状态，再依据控制器确认后的状态流式讲解。
- `TutorOrchestrator`：读书绕过通用摸底和课程评估，独立编排；完整回复后通过 `TutorStore` 一起保存 `bookStudy` 和对话，再发布 `book.study.updated`。
- `TutorState.bookStudy`：同会话按书保存章节、目标、笔记、用户理解、问题及证据，不创建共享的本地 `book-wiki` 目录。
- 控制器只接收能在本轮用户消息中找到的原话证据。准确、解释、应用、辨别四项；独立问题至少 3/4，近期平均至少 80%，并已有解释、举例和实践证据才可标掌握。复习间隔为 1、3、7、14、30、60 天，失败重置。证据语义由模型抽取，门槛和日期由代码决定。
- 主会话不再重复展示阅读进度卡片或输入框上方的操作按钮。阅读面板通过同源 `GET /api/conversations/:id/reading` 读取状态；BFF 校验会话归属后映射内部会话 ID，再向 Walry 获取公开笔记与进度，复习到期数按读取时间计算。接口不返回评分证据或完整对话。完成阅读回复后重新获取，失败时可在面板内重试。

## 启用

前端已有数据库需要运行 `npm run db:migrate`，更新 `cheerful_conversations.session_mode` 检查约束以允许 `read`；旧记录不变。现有 Docker 启动命令会自动运行该迁移。后端阅读状态复用现有 JSON 存储，无额外表迁移。

阅读面板这一轮调整无需新增数据库迁移；需同步更新前后端。使用 `npm start` 的环境需重新构建前端产物并重启，两端开发服务按各自源码监听方式更新。

按本次需求未运行前后端测试、构建或浏览器验收，交由用户验收。
